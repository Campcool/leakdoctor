## 授權與目標

使用者要求站在訪客需求優化 UI/UX，露涼社完成後明確指示「繼續優化下一個專案」。本輪僅灰汰郎官網，沿用先完整檢查、再發布、部署後等幾分鐘實際連線的流程。沒有修改 Bot、DNS、Crawler 政策、正式資料與訊息。以 GitHub 最新 main／open PR 核對，起工時無其他待合併 PR；中央 AI-skill main 為6dd7137aaeaa4bcb4f677cfe3caffaa2ccaea14a，讀取最新交付及本案規則。

受眾是想清洗、處理漏水或水量異常的住戶，也包含已詢問／已服務客戶。目的為先理解服務差異與費用，再準備資料並聯絡；視覺採既有深藍／青色、真實照片與清楚文字層次。

## 發現與設計取捨

- 原首頁六服務在兩組案例照片及安排流程之後，訪客需先讀重複證據才能比較範圍；移至四個任務捷徑後。原知識／價格模式仍在 Hero 前，價格導向訪客可直接跳轉。
- 既有文字卡與三欄大照片方案都會增加重複閱讀。採桌機兩欄「照片在左、服務資訊在右」，1050px以下單欄，600px以下照片獨立一列。照片 contain 全幅，標明現場紀錄／去識別；保留完整原始服務限制及前後案例。三欄大照片方案是版面推演，未稱已渲染或完成候選實測。
- 原地區入口主要導向抓漏，會混淆清潔範圍。首頁及 areas.html 分開說明居家五區與其他服務依地點、設備、排程確認；維持 areas 的 noindex,follow 與異頁 canonical，不擴張服務範圍。48／72小時附一般情況、旺季、滿檔與特定時段但書，不保證到府。
- 增加六項原生 details 準備清單，以及原 LINE 的改期／補資料／售後入口；不建立新的送單或傳訊流程。未知機型、地址、原因可稍後確認，不要求填假資料。

設計資料參考 AI-skill 保存之 UI/UX Pro Max products.csv 第31／55列（在地服務、居家修繕）及 ux-guidelines.csv 的固定導覽、歷史返回、深連結、觸控間距、焦點規則。經 GitHub 讀CSV，不冒稱執行未安裝的search.py；保留繁中字型與既有品牌，不補樣板認證、評論或服務成果。
